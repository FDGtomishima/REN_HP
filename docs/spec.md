# 個人ホームページ 構成・仕様書

Nov 17, 2026 · @tomishima

## 概要

事務所に所属する企業バーチャルライバー1名を紹介する非公式ファンサイトを、Astro の静的サイト（DB・自前サーバーなし）で作る。公式画像や紹介文を扱うため、事務所のガイドライン確認を開発より先に行う（「権利・ガイドライン」の節）。

- **目的**：ライバーのプロフィール、配信の歩み、実績をまとめて伝え、最新情報を発信する
- **ページ**：HOME / ABOUT / NEWS / HISTORY / ACHIEVEMENTS / CONTACT の6つ
- **見せ場**：ABOUT の衣装切り替えと、HISTORY の配信埋め込み付き年表（縦・横レイアウト切り替え）
- **方針**：表示の速さ・安全性・更新のしやすさを優先し、動きは要所に絞る。配信や実績が増えても YAML に追記するだけで反映できるようにする。サーバー側の処理は配信中判定だけに限定する

## 技術構成

すべて無料枠で始められる構成で、固定費用は独自ドメイン代（年1,000〜2,000円程度）のみを想定。

| 役割 | 使うもの | 備考 |
| --- | --- | --- |
| フレームワーク | Astro | 静的HTMLを生成。コンテンツコレクションでNEWSとYAMLデータを管理 |
| コード・記事の管理 | GitHub（privateリポジトリ） | pushで自動デプロイ |
| ホスティング | Cloudflare Workers（静的アセット配信） | HTTPS自動対応、`_headers` でセキュリティヘッダー設定。デモは Preview＋Cloudflare Access |
| 配信中判定 | Cloudflare Worker（Cron Trigger）＋KV | YouTube Data API、Twitch API を定期確認 |
| アニメーション | GSAP（ScrollTrigger）、CSS、Astro View Transitions | npmで導入（CDNは使わない） |
| 配信の埋め込み | YouTube（youtube-nocookie）、Twitch | クリックで読み込む方式 |
| お問い合わせ | 外部フォーム（Formspree / Tally / Googleフォーム / formrun から選択） | 自前でデータを持たない |
| デザイン | Figma | 動きはコードで試作して確認 |
| イラスト | 絵師への依頼 | 立ち絵（衣装・差分）、必要なら歩行アニメ |
| エフェクト | CSS（必要に応じて軽量な Canvas） | HOME 背景イラストに光・粒子・ズームなどの演出 |
| ドメイン | Cloudflare Registrar など | 構成を変えてもURLを維持できる |

更新が面倒になったら、Keystatic などのGitベースの管理画面を後から追加できる。

## ページ別仕様

6ページ構成で、更新が頻繁なのは NEWS のみ。HOME の最新情報は NEWS から自動で取得する。

```
HOME ──── NEWS 最新3件（src/content/news/）、配信中表示（/api/live）
ABOUT ─── src/data/profile.yaml、立ち絵（src/assets/outfits/）
NEWS ──── 一覧 / 記事ページ（src/content/news/）
HISTORY ─ src/data/history.yaml ──→ ACHIEVEMENTS の該当実績へリンク
ACHIEVEMENTS ─ src/data/achievements.yaml
CONTACT ─ 外部フォームへのリンク、プライバシーポリシー、src/data/credits.yaml
共通 ──── サイト名・非公式表記（src/data/site.yaml）
```

ページの中身はデータファイルから生成され、NEWS の記事は HOME の最新情報にも使われる。

### HOME

- **背景**：絵師に依頼したイラストを画面全体に表示し、エフェクトを重ねる（ゆっくりしたズーム、光の粒子、イメージカラーのグラデーションなど）。配信映像は使わない
- エフェクトは CSS 中心で軽く作る。粒子を多く出す場合だけ軽量な Canvas を使い、タブが非表示のときは止める
- イラストを「キャラクター」と「背景」にレイヤー分けしてもらえれば、マウスやスクロールに合わせて奥行きが出る演出（パララックス）も可能
- スマホでは粒子の数を減らす。「視差効果を減らす」設定のときは静止画のみ
- 上部にナビゲーション、下部に NEWS の最新 3 件と「一覧を見る」リンク。文字の下には半透明の帯を敷いて読みやすくする
- 画像は Astro の Image で最適化し、画面サイズに合わせた大きさで配信する
- 初期ロード演出は入れない
- **配信中の特殊演出**：「LIVE NOW」バッジ（押すと配信へ移動）と、画面の縁がイメージカラーで光る演出のみ。判定の仕組みは「配信中判定」の節を参照
- ヘッダーにも小さな「LIVE」マークを出し、他のページを見ている人にも配信中だと伝える（任意）

### ABOUT

上から「立ち絵 → 衣装選択 → 公式紹介文 → 基本情報 → SNS → タグ → よくやる配信」の順に並べる。PCは左に立ち絵・右に情報、スマホは縦並び。内容はすべて `profile.yaml` から生成する。

| 要素 | 仕様 |
| --- | --- |
| 立ち絵 | 絵師に依頼したイラストを衣装ごとに使用（公式画像は使わない）。差分（表情・髪型・小物など）があれば画像の横に切り替えボタン。画像の近くに絵師のクレジットとSNSリンク |
| 衣装選択 | 立ち絵の下に「1st / 2nd / 3rd …」のタブ。選択中の衣装名とお披露目日を表示。初期表示は最新の衣装 |
| 紹介文 | 個人で考えたオリジナルの文章。公式の紹介文は引用せず、「公式プロフィールはこちら」のリンクだけ置く |
| 誕生日・記念日 | 誕生日、デビュー日、その他の記念日。デビューからの日数は閲覧時にJSで計算（任意） |
| SNS | アイコン＋ユーザーIDを並べ、クリックで各SNSへ移動（新しいタブ、`rel="noopener"`）。アイコンは各社のブランドガイドラインに沿う |
| 各種タグ | 配信タグ、ファンアート（FA）タグ、ファンネーム（FN）。タグはクリックでXの検索結果へ移動、またはコピーボタン付き |
| よくやる配信 | 雑談、歌枠、ゲームなど、配信頻度が多い内容をカードで紹介。各カードに説明文と代表的な配信へのリンク |

### NEWS

- 内容を読ませることを最優先し、装飾やアニメーションは入れないシンプルな作りにする
- 一覧ページ：日付・カテゴリ・タイトルを新しい順に1行ずつ並べる。カテゴリ（お知らせ、配信予定、グッズ、コラボなど）で絞り込み
- 記事ページ：本文の読みやすさを重視（文字サイズ16px以上、行間ゆったり、1行の文字数を抑える）。日付、前後の記事へのリンク
- 記事ごとに SNS でシェアされたときのタイトルと説明（OGP）を設定
- 記事が増えたらページ送りと RSS を追加
- 1記事 = 1 Markdown ファイル（title / date / category を前書きに記述）

### HISTORY

デビュー日を起点に周年ごとに区切った年表。載せるのは節目の配信とビッグイベントのみ（すべての配信は載せない）。縦・横のレイアウトをボタンで切り替えられるので、PCでもスマホでも両方の表示を確認できる。

| 要素 | 仕様 |
| --- | --- |
| 周年選択 | 上部に「デビュー～1周年 / 1周年～2周年 / …」のタブ。区切りはデビュー日から自動計算。初期表示は現在の周年 |
| レイアウト切り替え | 「縦」「横」のボタン。初期値は画面幅で決め（PC＝横、スマホ＝縦）、選んだ方をブラウザに記憶。「視差効果を減らす」設定では初期値を縦にし、横を選んだ場合も GSAP の連動は使わず通常の横スクロールで表示する |
| 横レイアウト | 縦スクロールで右から左へ流れる（GSAP ScrollTrigger）。左に歩く人物を表示する演出はこちらでのみ使用 |
| 縦レイアウト | 中央の線に沿って上から下へ並ぶ通常のタイムライン。スクロールでふわっと表示 |
| 各ボックス | 日付、タイトル、テキスト、YouTube / Twitch の配信埋め込み。実績として登録済みの項目は、ボックスの角に小さなトロフィーアイコンを表示し、押すと ACHIEVEMENTS の該当実績（`/achievements/#ID`）へ移動してモーダルを開く |
| 未来の部分 | まだ来ていない周年・未登録の期間は「Coming Soon...」のボックスを表示 |

**配信埋め込みの注意点**

- 埋め込みをそのまま並べるとページが非常に重くなるため、最初はサムネイルと再生ボタンだけを表示し、クリックしたときにプレイヤーを読み込む方式にする
- YouTube はプライバシー強化版の `youtube-nocookie.com` を使う
- Twitch の埋め込みには公開先ドメインを `parent` に指定する必要がある（デモ用URLも含める）
- Twitch の過去配信は一定期間で自動削除されるため、残したいものはハイライト・クリップを指定する
- 非公開化・削除・メンバー限定の配信は埋め込めないため、テキストだけでも成り立つ書き方にする

### ACHIEVEMENTS

実績をカードで一覧表示し、クリックで `<dialog>` のモーダルに詳細を表示する（Esc・背景クリックで閉じる）。データは `achievements.yaml` で管理し、新しい順に並べる。

| 項目 | カード | モーダル | 備考 |
| --- | --- | --- | --- |
| 実績名 | 表示 | 表示 | 必須 |
| 日時 | 日付のみ | 日付＋時刻 | 必須 |
| 主催者 | 名前 | 名前＋SNSアイコンのリンク | 必須。複数可 |
| チームメンバー | — | 名前＋SNSリンクを一覧 | チーム戦のときだけ表示 |
| 元配信URL | — | リンク（任意で埋め込み） | 複数可（本人視点・公式配信など） |
| カテゴリ | ラベル | — | 大会、コラボ、出演、歌など。絞り込みタブに使用 |
| 結果・説明 | 結果（優勝など） | 結果＋説明文 | 任意 |

SNSリンクは X などの埋め込みウィジェットではなく、アイコン付きの通常リンクにする（表示が軽く、外部スクリプトも不要）。実績ごとに ID を振り、`/achievements/#ID` でそのモーダルを直接開けるようにして、HISTORY からリンクする。

### CONTACT

- お問い合わせ：外部フォームへのリンクボタンを設置（埋め込みはしない）
- フォームの近くに個人情報の扱い（返信のみに使用、外部サービスに保存）を一文で明記
- 項目は名前・メールアドレス・内容のみ。通知先と自動返信を設定
- 制作クレジット：`credits.yaml` の名前・担当・リンクを一覧表示（エンドロール風の演出も可）
- 掲載する方には名前・リンクの掲載了承を事前にもらう
- プライバシーポリシー：CONTACT ページ内の節として掲載（独立ページは作らない）。フッターからはこの節（`/contact/#privacy`）へリンク

## 配信中判定（HOME の特殊演出）

静的サイトはビルド時に中身が決まるため、「今配信中か」は別の小さな仕組みで判定する。このサイトで唯一、サーバー側の処理を持つ部分になる。

1. Cloudflare Worker を定期実行（Cron Trigger、数分おき）し、YouTube と Twitch の配信状態を確認
2. 結果（配信中か、タイトル、URL）を Cloudflare KV に保存
3. サイトはページを開いたときに `/api/live` からその結果を読み、配信中なら演出を表示

静的アセットの配信・`/api/live`・定期実行（Cron Trigger）は、サイトと同じ1つの Worker にまとめる（同じドメインで動くため CORS などの設定が不要）。

| 配信先 | 判定方法 | 注意点 |
| --- | --- | --- |
| YouTube | チャンネルのRSSで最新動画を取得し、YouTube Data API で配信中かを確認 | APIには1日の利用上限（クォータ）がある。検索APIは消費が大きいため使わない |
| Twitch | Twitch API の配信状態取得機能 | アプリ登録と秘密鍵が必要。ブラウザ側には置かない |

- 閲覧者が増えても外部APIへの問い合わせ回数は変わらない（確認は定期実行だけ）
- APIキーは Worker の「シークレット」に保存し、コードやGitHubには書かない
- 判定に失敗したときは演出を出さないだけで、ページの表示には影響させない
- 反映は数分遅れる。完全にリアルタイムにする必要はない
- `/api/live` へのアクセスは Worker の実行として数えられるため、結果に短いキャッシュを付けて無料枠に収める

## 共通部品とアニメーション方針

演出は HOME と HISTORY に集中させ、読ませるページ（ABOUT・NEWS）は控えめにする。

**共通部品**

- ヘッダー：サイト名（ロゴ）と各ページへのメニュー。スマホはハンバーガーメニュー。HOME では背景イラストの上に透過表示
- フッター：「非公式ファンサイトであり、事務所・ライバー本人とは関係ありません」の表記、コピーライト、SNSリンク（ライバー本人の SNS。`profile.yaml` から取得）、プライバシーポリシーへのリンク
- 共通レイアウト：`BaseLayout.astro` にまとめる

| 場所 | 演出 | 実装 |
| --- | --- | --- |
| 全ページ | ページ切り替えを滑らかに | Astro View Transitions（`ClientRouter`） |
| HOME | イラスト背景のエフェクト、配信中の特殊演出（初期ロード演出なし） | `CSS / Canvas`、`/api/live` |
| HISTORY | 縦・横レイアウト切り替え、（横のみ）歩く人物 | GSAP ScrollTrigger、CSS `steps()` |
| ACHIEVEMENTS | カードの順次表示、モーダルの開閉 | Intersection Observer、`<dialog>` |
| CONTACT | クレジットのエンドロール風表示（任意） | CSS アニメーション |

**共通ルール**

- OSの「視差効果を減らす」設定（`prefers-reduced-motion`）ではアニメーションを止める
- スマホでは重い演出を簡易版に切り替える

## データ管理とディレクトリ構成

更新頻度に合わせて管理方法を分け、どれもファイルを編集して push するだけで反映される。

| データ | 形式 | 場所 |
| --- | --- | --- |
| NEWS 記事 | Markdown（1記事1ファイル） | `src/content/news/` |
| プロフィール（衣装・SNS・タグ・記念日・よくやる配信） | YAML | `src/data/profile.yaml` |
| HISTORY 年表 | YAML | `src/data/history.yaml` |
| ACHIEVEMENTS 実績 | YAML | `src/data/achievements.yaml` |
| 制作クレジット | YAML | `src/data/credits.yaml` |
| 立ち絵（衣装・差分） | 画像 | `src/assets/outfits/`（Astro の Image で最適化） |
| サイト名・非公式表記 | YAML | `src/data/site.yaml` |
| 動画・その他の静的ファイル | 静的ファイル | `public/` |

```yaml
  - { service: youtube, id: "@xxxx", url: https://www.youtube.com/@xxxx }

  twitch_login: xxxx

  stream: "#○○配信"
  fanart: "#○○アート"
  fan_name: ○○さん

  - { title: 雑談, description: …, example: https://www.youtube.com/watch?v=xxxx }
```

**history.yaml の例**

```yaml
- date: "2024-04-01"
  title: 初配信
  text: デビュー配信。…
  embeds:
    - { platform: youtube, id: xxxxxxxxxxx }

```

**achievements.yaml の例**

```yaml
- id: cup-2025-summer
  title: ○○杯 2025 Summer

  category: 大会
  result: 優勝

  streams:
    - { label: 本人視点, url: https://www.youtube.com/watch?v=xxxx }

```

周年の区切りは `profile.yaml` の `debut` と各項目の `date` から自動で振り分けるため、周年ごとの入力は不要。

```
src/
├── pages/
│   ├── index.astro          … HOME
│   ├── about.astro          … ABOUT
│   ├── news/
│   │   ├── index.astro      … NEWS一覧
│   │   └── [slug].astro     … NEWS個別記事
│   ├── history.astro        … HISTORY
│   ├── achievements.astro   … ACHIEVEMENTS
│   └── contact.astro        … CONTACT
├── content/news/            … ニュース記事（Markdown）
├── data/                    … site / profile / history / achievements / credits のYAML
├── assets/outfits/          … 立ち絵（衣装・差分）
├── layouts/BaseLayout.astro … 共通ヘッダー・フッター
└── components/              … 衣装切替、SNSリンク、配信埋め込み、モーダルなど
public/
├── _headers                 … セキュリティヘッダー
└── (動画・favicon など)
```

**NEWS の更新フロー**

1. `src/content/news/` に Markdown ファイルを追加（GitHub のWeb画面からでも可）
2. GitHub に push
3. Cloudflare Workers（Workers Builds）が自動ビルド・デプロイし、NEWS 一覧と HOME の最新情報に反映

## 権利・ガイドライン

『ぶいすぽっ! 〜Virtual esports Project〜』の「二次創作・動画転載ガイドライン」（2026年9月17日改訂版）を確認した。個人による非営利のファン活動として運営すれば大部分は問題ないが、**HOME 背景は切り抜き動画をやめ、依頼イラスト＋エフェクトに変更した**。

| 項目 | 対応 | 確認結果 |
| --- | --- | --- |
| ファンサイト自体の運営 | 広告・アフィリエイト・投げ銭など収益になるものは一切置かない。個人名義で運営し、法人が費用を出す形にしない | OK（条件付き）。ガイドラインに「ファンサイト」の明記はないが、個人・非営利のファン活動は認められている。法人が主体の場合は対象外 |
| サイトの表示 | フッターに「非公式ファンサイトであり、事務所・ライバー本人とは関係ありません」と明記。サイト名・ドメイン名に「公式」「official」などを使わない | 必須。禁止事項7「公式コンテンツであるかのような誤解を招き得る表現」に該当しないようにする |
| 公式画像・ロゴ | 一切使わない（公式立ち絵のトレースや加工も不可） | NG。禁止事項2で、公式画像・ロゴのそのままの利用や創作性のない改変は一切許可されていない。事務所名はテキストでの紹介のみ |
| 絵師に依頼した立ち絵 | 絵師が新たに描いたイラストを使う。暴力的・グロテスク・性的な表現は不可。公式デザイン担当のイラストレーターへの依頼は避ける | OK（条件付き）。イラストは認められた二次創作。有償依頼は絵師側の「C. 少額の収益が発生する活動」（年間20万円以下）に該当するため、依頼時に絵師へ伝える。公式デザイン担当のイラストレーターには別ルールがある |
| AIで作った画像 | 使う場合は AI イラストであることを明記。基本は使わない | SNSやWebサイトへの投稿時は「#AIイラスト」必須、ファンアートタグの使用は不可 |
| 紹介文 | 自作の文章。公式プロフィールと内容が食い違わないか確認 | OK |
| HOME 背景（イラスト＋エフェクト） | 依頼イラストに CSS などのエフェクトを重ねる。配信映像は使わない。イラストの加工・レイヤー分け・動かすことは絵師の了承を得る | OK（条件付き）。二次創作イラストの扱いになり、転載動画の申請は不要。画像に公式ロゴや公式画像を入れない |
| 配信の埋め込み | YouTube / Twitch の公式埋め込みプレイヤーを使う。動画のダウンロードや再アップロードはしない | OK。禁止されているのは許可なく動画を転載することで、配信サイトの埋め込み機能は転載に当たらない |
| 他のメンバー・主催者 | 公開SNSへのリンクのみ。画像は載せない | OK |
| サイトの内容・表現 | ブランドイメージを損なう表現、差別的・政治的な内容、誇張した表現を入れない | 必須。禁止事項3・8・9・11 |

**HOME 背景の扱い（案Aに決定）**

- 案A（推奨）：絵師に依頼したイラストを背景にし、CSSでゆっくり動かす（ズーム、光の粒子、グラデーション）。ガイドライン上の申請が不要で、動画より軽い
- 案B：切り抜き申請フォーマットからサイト名・URLを申請して許諾番号を取得し、字幕や演出を加えた創作性のある編集動画にする。許諾番号と元配信URLをサイトに明記。背景用の短いループで創作性が認められるかは不確実で、事前に vspo-clip の窓口へ問い合わせた方がよい
- 案C：公式や本人が公開している動画を YouTube の埋め込みで背景に敷く。転載には当たらないが、読み込みが重く、YouTube の操作ボタンが一瞬表示されるなど見た目の制約がある

問い合わせ先：二次創作は vspo-guide@virtual-entertainment.co.jp、動画転載は vspo-clip@virtual-entertainment.co.jp（回答まで約1週間）。ガイドラインは予告なく改訂されるため、公開前と定期的に最新版を確認する。

**どちらの場合も守ること**

- イラストレーターや Live2D モデラーのクレジットは、公式の表記に合わせて CONTACT の制作クレジットと衣装ごとに記載する
- 他のライバー（チームメンバー、主催者）は、公開されているSNSへのリンクにとどめ、その人の画像は載せない（各事務所のガイドラインが異なるため）
- 中の人に関する情報や、公式が公開していない情報は掲載しない
- SNSアイコンは各社のブランドガイドラインに沿って使う
- ガイドラインは改定されることがあるため、確認した日付を記録しておく

## セキュリティ・プライバシー対策

DB・管理画面・自前サーバーがないため、サイト自体への攻撃リスクは低い。注意すべきは「管理アカウントの乗っ取り」と「個人情報の出しすぎ」。

- [ ] GitHub・ホスティング・ドメイン・外部フォームの各アカウントで2段階認証を有効化
- [ ] パスワードは使い回さず、パスワードマネージャーで管理
- [ ] GitHubリポジトリを private にする
- [ ] `.env` を `.gitignore` に追加し、秘密情報（YouTube・Twitch のAPIキーなど）は Worker のシークレットで管理
- [ ] 外部フォームのスパム対策を有効化、項目は最小限
- [ ] フォーム付近とフッターからプライバシーポリシーを確認できるようにする
- [ ] `package-lock.json` をコミットし、Dependabot を有効化
- [ ] `public/_headers` でセキュリティヘッダーを設定
- [ ] 写真の位置情報（EXIF）を削除してから掲載し、生活圏が分かる情報は出さない
- [ ] 制作クレジット掲載者から了承を得る

```
/*
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=()
```

後から管理画面（Keystatic など）を追加する場合は、GitHub ログイン経由の認証にして自分以外が入れないようにする。外部フォームはリンクで案内するため、埋め込み用の許可設定は不要。
